Context: `rust-use` is a Cargo workspace (see root `Cargo.toml`, crates under `crates/`).
`rust-use-gpui` depends on `gpui` 0.2.2, which builds on macOS (Metal) and on Linux only with

## Files to create

### `.github/workflows/ci.yml`
- Triggers: push to `main`, pull_request, workflow_dispatch. `concurrency` group per ref with cancel-in-progress.
- `permissions: contents: read`. Env: `CARGO_TERM_COLOR: always`, `RUSTFLAGS: -Dwarnings`.
- Use `actions/checkout@v4`, `dtolnay/rust-toolchain@stable` (with components where needed), `Swatinem/rust-cache@v2`.
- Jobs:
  1. `fmt` (ubuntu-latest): `cargo fmt --all --check`.
  2. `core` (matrix ubuntu-latest, windows-latest): clippy + test + doc for every crate EXCEPT the gpui crate and the facade's gpui feature:
     `cargo clippy --workspace --exclude rust-use-gpui --all-targets -- -D warnings`,
     `cargo test --workspace --exclude rust-use-gpui`,
     `cargo test -p rust-use --no-default-features` (facade builds with no features),
     `cargo doc --workspace --exclude rust-use-gpui --no-deps` with `RUSTDOCFLAGS: -Dwarnings`.
     Note: the facade must not enable `gpui` here; plain `--workspace` builds default features only, which is correct.
  3. `macos` (macos-latest): the full gate with all features:
     `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
     `cargo test --workspace --all-features`,
     `cargo doc --workspace --no-deps --all-features` (RUSTDOCFLAGS -Dwarnings).
  4. `msrv` (ubuntu-latest): reads `rust-version` from the workspace via
     `cargo metadata --no-deps --format-version 1 | jq -r '.packages[] | select(.name=="rust-use-core") | .rust_version'`, installs that toolchain with `dtolnay/rust-toolchain@master` (`toolchain: ${{ steps.msrv.outputs.version }}`), runs `cargo check --workspace --exclude rust-use-gpui`.
  5. `deny` (ubuntu-latest): `EmbarkStudios/cargo-deny-action@v2`.
  6. `package` (ubuntu-latest): `cargo package -p rust-use-core --allow-dirty` (dry packaging of the leaf crate; others depend on unpublished versions until the first release).

### `.github/workflows/publish.yml`
Model it on this design (from a sibling project; keep the explanatory header comment style — a block comment at the top explaining WHY the release, not the tag, is the trigger, how auth works, and the one-time setup):
- `on: release: types: [published]` and `workflow_dispatch` with boolean input `dry-run` default true.
- `permissions: contents: read, id-token: write`.
- Job `publish` on `macos-latest` (gpui crate must build), `if: github.event_name == 'workflow_dispatch' || startsWith(github.ref_name, 'v')`.
- Steps: checkout, toolchain, rust-cache, the full gate (clippy all-features -D warnings, test all-features).
- "Check the tag matches the workspace version" (release only): compare `${GITHUB_REF_NAME#v}` with the version from `cargo metadata` for package `rust-use`; fail with `::error::` if different.
- Auth (release only): `rust-lang/crates-io-auth-action@v1` with `id: auth`; then `CARGO_REGISTRY_TOKEN: ${{ steps.auth.outputs.token || secrets.CARGO_REGISTRY_TOKEN }}` so the very first release can fall back to a repository secret (crates.io only allows trusted publishing for crates that already exist). Give the auth step `continue-on-error: true` so the fallback works on the first release, and explain this in a comment.
- Publish in dependency order, one `cargo publish -p <crate>` per crate: rust-use-core, rust-use-macros, rust-use-agent, rust-use-gpui, rust-use-cli, rust-use. Make it a small bash loop that skips a crate whose exact version is already on crates.io (check with `cargo search <crate> --limit 1` or `curl -sf https://crates.io/api/v1/crates/<crate>/<version>`), so a re-run after a partial failure resumes instead of failing.
- Dry-run (workflow_dispatch): `cargo publish -p rust-use-core --dry-run` and `cargo package --workspace --no-verify` is NOT valid for unpublished deps — so dry-run only the leaf crates that have no unpublished internal deps (`rust-use-core`, `rust-use-macros`, `rust-use-cli`), with a comment explaining why.
