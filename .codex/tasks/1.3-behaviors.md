# Task 1.3 — The 0.1.0 behaviors

Read first: `crates/rust-use-core/src` (Behavior, Describe, Args, ActionSpec/ParamSpec, Query,
Page, ActionError) and `crates/rust-use-macros` (you may use `#[actions]`-style code generation
only if rust-use-core can depend on it without a cycle — it cannot, so hand-implement `Behavior`
in core; keep each impl tight and table-driven). **Do NOT run `git commit`.**

Put them in `crates/rust-use-core/src/behaviors/{mod,press,toggle,value,selection,list,roving_focus,typeahead,popup,drag_drop}.rs`,
re-exported flat from the crate root and from the facade root (and the common ones in the prelude:
`Toggle, Value as ValueOf?` — NO: name the value behavior `Field<T>` to avoid clashing with
`serde_json::Value`).

Each behavior is a plain struct usable on its own (typed Rust API for app code) and as a
`#[behavior]` field inside a primitive (agent API through `Behavior`). App-facing methods take
`&mut self` and return useful results; the `Behavior` impl is a thin layer over them.

Agent-visible names must be short (they are tokens). Attribute and action names below are the contract.

| Behavior | State / typed API | describe | actions |
|---|---|---|---|
| `Press` | `presses: u64`, `press()`, optional `on_press: Option<Box<dyn FnMut() + Send>>` set via `Press::new().on_press(f)` | nothing (or `pressed` flag while `is_pressed` during a GUI press — add `set_pressed(bool)`) | `press` |
| `Toggle` | `on: bool`, `toggle()`, `set(bool)`, `is_on()` | value = on | `toggle`, `set(on:bool)` |
| `Field<T: Serialize + DeserializeOwned + Clone + Send>` | `get() -> &T`, `set(T)`, optional validator `with_validator(fn(&T)->Result<(),String>)` | value = T | `set(value:any)`; validation failure → `ActionError::Rejected` |
| `Selection<K: Serialize + DeserializeOwned + Eq + Clone + Send>` | `mode: SelectionMode::{Single, Multiple}`, `selected() -> &[K]`, `select(K)`, `deselect(&K)`, `toggle(K)`, `clear()`, `is_selected(&K)` | attr `sel` = K (single) or list (multiple); omitted when empty | `select(key:any)`, `deselect(key:any)` (multiple only → `is_enabled` false in single mode), `clear` (enabled only when non-empty) |
| `List<T: Serialize + Send>` | `items: Vec<T>`, `push`, `remove(i)`, `move_item(from,to)`, `len`, `iter`, `filter: Option<Box<dyn Fn(&T,&str)->bool + Send>>` (default: case-insensitive substring on the item's serialized string) | attr `n` = len | `move(from:int,to:int)`; `query` → `Page::from_iter` over items matching text |
| `RovingFocus` | `Orientation::{Horizontal, Vertical, Grid { columns }}`, `len`, `active: Option<usize>`, `wrap: bool`, `next()`, `prev()`, `up()/down()/left()/right()` for grid, `first()`, `last()`, `focus(i)`; a typed `handle_key(Key) -> bool` with `pub enum Key { Up, Down, Left, Right, Home, End }` | attr `focus` = index (omit when None) | `focus(index:int)` only — arrow-key navigation is for humans; agents jump directly |
| `Typeahead` | buffer + timeout (`Duration`, default 500ms) + `push_char(c, now: Instant, labels: &[&str]) -> Option<usize>` matching prefix case-insensitively, cycling when the same char repeats | nothing | none (human-only behavior; it still implements Behavior with empty describe so it can be embedded) |
| `Popup` | `open: bool`, `open()`, `close()`, `toggle()`, `modal: bool` | flag `open` | `open` (enabled when closed), `close` (enabled when open) |
| `DragDrop<Id: Serialize + DeserializeOwned + Clone + Send>` | typed: `start(Id)`, `over(Option<Id>)`, `drop_on(Id) -> Option<(Id, Id)>`, `cancel()`, `dragging() -> Option<&Id>`; plus `on_drop(f: FnMut(Id, Id) -> Result<(), String>)` callback | attr `drag` = id while dragging | `drop(from:any,to:any)` — the agent performs a drag atomically, calling on_drop; never a multi-step pointer sequence |

## Rules
- Every behavior: `Default` where sensible, `Debug` (manual impl for those holding closures),
  doc comment with a short example of typed use AND of embedding it with `#[behavior]` in a
  primitive (those embedding examples belong in the FACADE docs where macros exist — in core,
  show typed use only, and write the embedding examples as tests in `crates/rust-use/tests/behaviors.rs`).
- `Behavior::actions()` must return a `Vec` built from `const` `ActionSpec` arrays (no per-call
  string allocation).
- Integration tests in `crates/rust-use/tests/behaviors.rs`: for each behavior, a primitive
  embedding it via `#[derive(Primitive)] #[primitive(no_actions)]` + `#[behavior]` field, mounted
  in a `Ui`, driven through `Ui::invoke` with `ChangeSource::Agent`, asserting describe output and
  enabled/disabled actions. Plus typed unit tests in core for edge cases: grid navigation at edges
  with/without wrap, typeahead cycling and timeout, selection single-mode replacement,
  list move bounds errors, DragDrop drop with failing callback (state unchanged, error Rejected).

## Acceptance
Full gate passes. No `unwrap/expect` outside tests. No new dependencies.
