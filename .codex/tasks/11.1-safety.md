# Task 11.1 — Agent safety: secrets, hidden components, actions that need a person

Read AGENTS.md, `crates/rust-use-core/src/{ui.rs,action.rs,describe.rs,behavior.rs}`,
`crates/rust-use-macros/src/{derive.rs,action.rs}`, `crates/rust-use-agent/src/{agent.rs,format.rs}`
and `FORMAT.md`. **Do NOT run `git commit`.** This is the riskiest change in 0.2: it touches the
invoke path and adds blocking. Keep locks out of every callback (see "Locks").

## What an agent must not see, and must not do alone

### 1. Secrets: `#[agent(secret)]`
On a field (value, attribute or flag), the derive writes the literal string `[redacted]` instead of the
field's value, for both `#[agent(value)]` and plain attributes. Flags are not secret-able (compile
error: "a flag shows only true/false; it can't be secret"). It is also a compile error on a
`#[behavior]` field. The field still needs no `Serialize` bound when it is secret. Document in the derive
docs that secrets cover fields only, not items a behavior returns from `query`.

### 2. Hidden components
- `Primitive` gets `const HIDDEN: bool = false;` and `#[primitive(hidden)]` sets it.
- `Ui` stores a `hidden: bool` per entry, initialised from `P::HIDDEN` at mount.
  `Handle::hide_from_agents(&self)` and `Handle::show_to_agents(&self)` toggle it. Each real change
  bumps the revision with `ChangeKind::Visibility`.
- `ComponentInfo` gets `pub hidden: bool`.
- **Agents never see or reach a hidden component:**
  - `Ui::invoke(.., ChangeSource::Agent)` on a hidden target fails with `ResolveError::NotFound` (as
    if it didn't exist). Label and kind resolution for agent-sourced calls must skip hidden entries
    before deciding ambiguity, so the error can't leak that one exists.
  - Add `Ui::resolve_for(&self, r, source)` (or an equivalent internal path) used by the agent crate.
  - The agent crate filters hidden components from `snapshot`, `search` and `query`.
  - `diff` reports a component that became hidden as a removal line `-@id`, and one that became
    visible as a changed line.

### 3. Actions that need a person: `#[action(confirm = "Delete the project")]`
- `ActionSpec` becomes `#[non_exhaustive]` with a new `pub confirm: Option<&'static str>`. Add
  `pub const fn ActionSpec::new(name, doc, params) -> Self` and
  `pub const fn confirm(self, text: &'static str) -> Self`, and migrate every struct literal in the
  workspace to them (behaviors' `action` helper, macros, tests, docs). `ParamSpec` gets the same
  `#[non_exhaustive]` + `new`/`optional()` treatment for future-proofing.
- `ActionRequest` gets `pub confirm: Option<&'a str>`.
- **Enforcement lives in `Ui::invoke`**, so it holds however an agent connects: when
  `source == ChangeSource::Agent` and the action's spec has `confirm`:
  - with no approver installed → `InvokeError::Denied(format!("needs a person: {confirm}"))`;
  - with an approver → call it (after the normal interceptors, with no locks held). Approved →
    run; denied or timed out → `InvokeError::Denied(reason)`.
- Snapshot rendering: an action that needs a person is written with a double bang: `!!delete(id)`.
  Spec it in FORMAT.md. Verbose docs append ` (needs a person: <text>)`.

### 4. `Approvals`: a person answers, the agent waits (in rust-use-core, re-exported everywhere)
```rust
/// Pending agent actions waiting for a person. Clone is cheap (Arc). Send + Sync.
pub struct Approvals { .. }
impl Approvals {
    pub fn new() -> Self;                                   // timeout defaults to 5 minutes
    pub fn timeout(self, timeout: Duration) -> Self;
    pub fn pending(&self) -> Vec<PendingApproval>;          // oldest first
    pub fn approve(&self, id: u64) -> bool;                 // false if unknown or already decided
    pub fn deny(&self, id: u64, reason: impl Into<String>) -> bool;
    /// Called (outside any lock) whenever a request starts waiting, e.g. to wake a GPUI view.
    pub fn on_request(&self, f: impl Fn(&PendingApproval) + Send + Sync + 'static) -> Subscription;
}
#[derive(Debug, Clone)]
pub struct PendingApproval { pub id: u64, pub component: ComponentId, pub label: Option<String>,
    pub action: String, pub args: Args, pub confirm: &'static str, pub requested: std::time::Instant }
impl Ui { pub fn require_approval(&self, approvals: &Approvals) -> Subscription; } // one approver at a time; replacing is allowed
```
The waiting step blocks the calling thread on a `Condvar` (with `wait_timeout`). That's the IPC
connection thread, or the caller of `Agent::act`. Never require the UI thread: document that
`Agent::act` called on a GUI thread with an approver installed would block that thread, and that
apps should drive agents from a background thread (IPC already does). Timeout →
`Denied("no answer from a person within <duration>")`. Dropping the `Subscription` from
`require_approval` releases any waiters with `Denied("approvals were turned off")`.

## Locks (must hold, test them)
- No registry, component or approvals lock is held while calling interceptors, the approver,
  `on_request` callbacks or subscribers.
- While one agent step waits for approval, other threads can `snapshot`, `read` and `invoke`
  other components (test: a waiting step on a background thread; meanwhile the main thread
  snapshots, invokes something else, then approves).

## Tests
- Derive: secret value and attribute render `[redacted]`. trybuild: `secret` on a flag, `secret` on
  a behavior, unknown `primitive(...)` key, `confirm` with a non-string value.
- Hidden: absent from snapshot and search; `query`/`invoke` from the agent report not found; a label
  shared with a hidden component is not ambiguous for agents; hide shows as `-@id` in diff, show brings it back.
- Confirm: `!!delete` rendering; without an approver → "needs a person: …"; approve → runs; deny
  with reason; timeout (use 50 ms); dropping the approver subscription releases a waiter; user-sourced
  invokes of confirm actions are NOT gated.
- IPC end to end (`crates/rust-use-agent/tests/ipc.rs`, feature ipc): a client's `act` blocks until
  the server side approves via `Approvals::approve`.
