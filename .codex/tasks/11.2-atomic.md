# Task 11.2 — Atomic `act`: all steps or none

Read AGENTS.md, `crates/rust-use-core/src/ui.rs` (invoke path, revisions, change events),
`crates/rust-use-macros/src/derive.rs`, `crates/rust-use-agent/src/{agent.rs,parse.rs,types.rs}` and
`FORMAT.md`. **Do NOT run `git commit`.**

## Behavior
Today a failing step leaves earlier steps applied. With atomic, a failure restores every component
the script touched to its state before the script, and the reply says nothing changed.

## Design
- **Opt-in per primitive: `#[primitive(checkpoint)]`**, which requires `Clone` (compile error
  otherwise, via a trait bound with a clear message). It implements a new provided `Primitive` hook,
  roughly `fn checkpoint(&self) -> Option<Box<dyn Any + Send>>` and `fn restore(&mut self, saved: Box<dyn Any + Send>)`,
  with defaults `None` and no-op. Hand-written primitives can implement them too. Document both.
- **`Ui::transaction(&self, f: impl FnOnce(&Tx) -> Result<T, E>) -> Result<T, E>`**, or a simpler internal
  API the agent uses. Before the first step touches a component, save its checkpoint. On error, restore
  every saved component in reverse order, then emit ONE change event per restored component
  (`ChangeKind::Restored`). The revision moves forward, never backward, because subscribers already
  saw the intermediate changes. Keep the lock rules: no lock held across interceptors or approval waits.
- **Up-front validation:** before running anything, resolve every step's target. If any target is
  not checkpointable, fail immediately with
  `ActError::NotAtomic { step, component }` → `err <i> <step>: @3 slider can't be rolled back (add #[primitive(checkpoint)])`.
  Nothing runs.
- **Agent API:** `Script::atomic(self) -> Self`; text syntax: a script whose first line is `atomic`
  (e.g. `atomic; board move e2e4; board move e7e5`). CLI: `rust-use act --atomic "…"`. MCP `act`
  tool: optional `atomic: bool` (keep the description budget test passing).
- **Reply on rollback:** `err <i> <step>: <message>` then `rolled back` then the diff (which shows
  the restored components at their original state, or just the `rev` line if nothing visible differs).

## Tests
- A two-step atomic script whose second step fails leaves the first component unchanged, and the
  reply contains `rolled back`.
- A non-checkpoint target fails before anything runs (assert no revision change).
- Non-atomic scripts behave exactly as before (existing tests untouched).
- Chess: make the demo's `Board` `#[primitive(checkpoint)]` (it's `Clone`-able: the cozy-chess
  position is Clone; derive Clone on `Board`), and add a test where `atomic; board move e2e4; board move e2e5`
  leaves the board at the start position.
