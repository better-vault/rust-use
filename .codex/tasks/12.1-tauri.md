## API (contract), in `crates/rust-use-tauri/src/lib.rs`
```rust
/// A Tauri plugin that serves a rust-use `Ui` to the webview and to agents.
pub fn init<R: tauri::Runtime>(ui: Ui) -> tauri::plugin::TauriPlugin<R>;
/// Same, with options.
pub fn builder(ui: Ui) -> PluginBuilder;
pub struct PluginBuilder { .. }
impl PluginBuilder {
    /// Also serve the Ui over rust-use IPC under this app name (feature "ipc"), so `rust-use --app <name>` works.
    #[cfg(feature = "ipc")] pub fn serve_ipc(self, name: &str) -> Self;
    /// Only let agents run actions the predicate accepts (same as Agent::allow).
    pub fn allow(self, f: impl Fn(&ActionRequest<'_>) -> bool + Send + Sync + 'static) -> Self;
    pub fn build<R: tauri::Runtime>(self) -> tauri::plugin::TauriPlugin<R>;
}
```
The plugin, named `rust-use`:
- manages the `Ui` as state (`app.manage`);
- registers commands, called from JS as `plugin:rust-use|<name>`:
  - `snapshot()` → the compact text; `snapshot_json()` → `Snapshot::to_json()` for UIs that render from it;
  - `act(script: String)` → the act reply text, with `ChangeSource::Agent` (for an in-app agent);
  - `invoke(target: String, action: String, args: Vec<serde_json::Value>)` → the action's return value
    as JSON, with **`ChangeSource::User`**: this is how the webview's own buttons change state, so people
    and agents share one path and the same allow checks;
  - `query(target: String, text: Option<String>, from: Option<usize>)`;
- in `setup`, subscribes to `Ui` changes and emits `rust-use://changed` with payload
  `{ "revision": u64, "ids": [u32] }`. Coalesce bursts: at most one emit per change batch. Use a
  dedicated thread with a channel that drains, since emits come from any thread. Keep the
  `Subscription` alive for the app's lifetime (store it in managed state).
- ships `permissions/default.toml` that allows all five commands, plus `build.rs` with
  `tauri_plugin::Builder::new(COMMANDS).build()` **only if** that crate is available offline in the
  cargo cache. If it isn't, ship the permissions TOML written by hand and note in the README how an
  app enables it (`"rust-use:default"` in capabilities).

## Docs
- Crate docs and a README with: setup in `main.rs` (5 lines), the capability line, and a ~30-line
  plain-JS snippet (no framework, no npm package) that calls `snapshot_json`, renders a toggle,
  calls `invoke` on click, and re-renders on `rust-use://changed`. The snippet can be `ignore`d in tests.
- Facade: feature `tauri = ["agent", "dep:rust-use-tauri"]`, re-exported as `rust_use::tauri`.
  Never enabled by `all-features` builds on Linux CI unless it builds there (see CI below).

## Tests (mock runtime)
- Build an app with `tauri::test::mock_builder().plugin(rust_use_tauri::init(ui.clone()))` and
  `mock_context(noop_assets())`. Use `get_ipc_response` to call `plugin:rust-use|snapshot`,
  `|invoke` (assert that the change carries `ChangeSource::User`, via a `Ui::subscribe` recorder) and
  `|act` (assert `ChangeSource::Agent`).
- Event: listen for `rust-use://changed` in the mock app, change the Ui from another thread, and
  assert one event arrives with the right ids.
- allow: a denied agent action through `|act` returns the `err` reply.

## CI
Add `rust-use-tauri` to the publish order in `.github/workflows/publish.yml` (after `rust-use-gpui`,
before `rust-use-cli`). In `ci.yml`, run its tests on macOS (the all-features job covers it). On
Linux, try it: if the mock runtime needs system packages there, exclude it in the Linux jobs like
`rust-use-gpui`, with a comment saying so.
