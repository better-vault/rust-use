## Part A — MCP adapter in rust-use-agent (feature `mcp`)
`crates/rust-use-agent/src/mcp.rs`, behind `mcp = ["dep:rmcp", "dep:tokio", "dep:schemars"]`.
Facade: `mcp = ["agent", "rust-use-agent/mcp"]` re-exports `rust_use::mcp::*`.

```rust
/// Anything that answers the text protocol. Implemented for Agent and ipc::Client (behind a Mutex).
pub trait Endpoint: Send + Sync + 'static { fn handle(&self, request: &str) -> String; }

/// An MCP server exposing exactly three tools: `snapshot`, `act`, `query`.
pub struct McpServer<E: Endpoint> { … }
impl<E: Endpoint> McpServer<E> {
    pub fn new(endpoint: E) -> Self;
    /// Serve over stdio until the client disconnects. Creates its own current-thread tokio runtime
    /// when called outside one (so library users do not need tokio).
    pub fn serve_stdio(self) -> Result<(), McpError>;
}
```
Tool definitions — descriptions are tokens the model reads on EVERY request, so keep them short
and precise (total for all three ≤ 600 characters). Inputs:
- `snapshot { verbose?: bool }` → text content: the compact snapshot.
- `act { script: string }` → text content: the act reply (`ok …` or `err …`). Describe the
  script syntax in one line: `"<ref> <action> [args]" steps separated by ";" — ref is @id, label or kind`.
- `query { ref: string, text?: string, from?: int }`.
Replies are plain `text` content (the compact format), not JSON. `err` replies set `is_error: true`.
Server info: name `rust-use`, version from `CARGO_PKG_VERSION`, instructions: one sentence telling
the model to call `snapshot` once, then `act` (which returns what changed) — no repeated snapshots.

Test (in rust-use-agent, feature `mcp`): drive the server in-process with an rmcp client over a
`tokio::io::duplex` pair (see rmcp tests for how), list tools (assert names and that combined
description length ≤ 600), call `act` and `snapshot` against an in-process Agent.

## Part B — the CLI (`crates/rust-use-cli`)
Depends on rust-use-agent with features `ipc` and `mcp`. Binary name `rust-use`.

```
rust-use [--app <name>] snapshot [--verbose]
rust-use [--app <name>] diff
rust-use [--app <name>] act <script>...       # remaining args joined with spaces
rust-use [--app <name>] query <ref> [text] [--from N]
rust-use [--app <name>] raw <payload>...      # send any payload (custom commands)
rust-use list                                  # live endpoints, one per line
rust-use [--app <name>] mcp                    # MCP shim over stdio, relaying to the app
```
- `--app` defaults to env `RUST_USE_APP`, else `Client::connect_default()`.
- Prints the reply to stdout exactly (no decoration — it is consumed by an agent). Exit code 1
  when the reply starts with `err`, 2 on connection errors (message on stderr, one line, saying
  how to fix: e.g. "no rust-use app is running; start one with the `ipc` feature enabled").
- `diff` across separate CLI invocations: each invocation is a new connection, so a per-connection
  last-seen revision would always be 0. Fix: the CLI persists the last seen revision per app in a
  small state file in the same runtime dir as the socket (`<name>.rev`), and sends
  `diff <rev>` (add support for an explicit revision argument `diff <n>` to `Agent::handle` and
  FORMAT.md). After `snapshot`/`act`/`diff` it stores the reply's `rev` line. This keeps the
  native path as token-lean as a persistent session.
- Keep `main.rs` small: `cli.rs` (clap), `commands.rs`, `state.rs`.
- Integration test (`tests/cli.rs`): spawn an in-process `ipc::Server` on a unique endpoint in the
  test, run the built binary (`env!("CARGO_BIN_EXE_rust-use")`) with `--app`, check snapshot,
  act, diff (second diff after no change prints only `rev N`), exit codes, and `raw`.
