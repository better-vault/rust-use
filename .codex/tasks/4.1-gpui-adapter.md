own sources at `~/.cargo/registry/src/*/gpui-0.2.2` (examples/, src/app/context.rs for

Work in `crates/rust-use-gpui`. `futures = "0.3"` is in the cargo cache (gpui depends on it too).

## Why
App state lives in rust-use primitives inside a `Ui` (Send + Sync; agents may change it from an
IPC thread). A GPUI view renders from that state and must re-render when ANY source changes it,
and GUI events must go through the same action path as agents so both are recorded and vetoable
identically.

## Public API (contract)

```rust
/// Keeps a GPUI entity re-rendering whenever the Ui changes. Store it in the view struct;
/// dropping it stops the observation.
pub struct UiBinding { _subscription: rust_use_core::Subscription, _task: gpui::Task<()> }

pub trait UiExt {
    /// Observe every change in this Ui (from any thread) and call `cx.notify()` on the entity
    /// that owns `cx`. Bursts of changes are coalesced into one notify per frame/turn.
    fn bind<V: 'static>(&self, cx: &mut gpui::Context<V>) -> UiBinding;
    /// Like `bind`, but only for changes to the listed components.
    fn bind_to<V: 'static>(&self, ids: &[ComponentId], cx: &mut gpui::Context<V>) -> UiBinding;
}
impl UiExt for Ui { … }

pub trait HandleExt<P: Primitive> {
    /// A click listener that invokes `action` with `args` as `ChangeSource::User`.
    /// Errors (vetoed, disabled, rejected) are passed to the optional `on_error` set with
    /// `.on_error(..)`… keep it simple: errors are logged via `log`-free `eprintln!` ONLY in debug
    /// builds (`cfg(debug_assertions)`), ignored in release. Signature must be directly usable as
    /// `div().on_click(handle.on_click("press", ()))`.
    fn on_click(&self, action: &'static str, args: impl Into<Args>) -> impl Fn(&gpui::ClickEvent, &mut gpui::Window, &mut gpui::App) + 'static;
    /// Same for mouse-down (for drag starts / board squares).
    fn on_mouse_down(&self, action: &'static str, args: impl Into<Args>) -> impl Fn(&gpui::MouseDownEvent, &mut gpui::Window, &mut gpui::App) + 'static;
}
impl<P: Primitive> HandleExt<P> for Handle<P> { … }
```
(Adjust closure parameter types to whatever gpui 0.2.2's `on_click` / `on_mouse_down` actually
take. `Args` must be `Clone` for this; it already derives Clone.)

Mechanism for `bind`: `ui.subscribe` pushes into a `futures::channel::mpsc::unbounded` sender (Send);
`cx.spawn(async move |this, cx| { while rx.next().await.is_some() { drain pending with try_next; this.update(cx, |_, cx| cx.notify())?-break on error } })`.
Return `UiBinding { subscription, task }`.

Prelude: `pub mod prelude { pub use crate::{UiExt, HandleExt, UiBinding}; }`. Facade feature
`gpui` re-exports `rust_use::gpui::*` and adds `UiExt, HandleExt` to `rust_use::prelude` under
`cfg(feature = "gpui")`.

## Example — `crates/rust-use/examples/gpui_counter.rs` (`required-features = ["gpui"]`)
A window with a counter primitive (`#[derive(Primitive)]`, actions `increment`, `reset`), a
button using `handle.on_click("increment", ())`, the count text rendered via `handle.read`, and
a background thread (std::thread) that every 2 s calls
`ui.agent().act("counter increment")` (feature agent) to demonstrate the view updating from an
agent on another thread. Keep it under 120 lines, nicely styled (rounded card, centered).

## Tests
