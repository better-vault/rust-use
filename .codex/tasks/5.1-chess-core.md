## The point of this demo
It is the benchmark. Claude Code plays the same game through two very different interfaces to
the SAME running app, and we measure calls, tokens and time:
- **rust-use**: `board move e2e4` through the agent bridge (CLI over IPC, or the MCP shim).
- **Baseline**: what generic UI automation gives an agent today — an accessibility-style tree of
  every element, and clicks by element id (like Playwright/computer-use/browser MCP tools). A move
  = click from-square, click to-square, then read the tree again to see the result.
Both must be honest and correct. Do not make the baseline artificially bad (no pretty-printing,
no junk fields) or rust-use artificially good.

## `src/board.rs` — the `Board` primitive (name "board")
```rust
#[derive(Primitive)]
#[primitive(name = "board")]
pub struct Board {
    #[agent(value)] fen: String,           // kept in sync with `position`
    turn: char,                            // 'w' | 'b'
    #[agent(flag)] check: bool,
    last: Option<String>,                  // last move in UCI, omitted when None (null attrs are dropped by the format)
    status: Option<&'static str>,          // "checkmate" | "stalemate" | "draw" — None while playing
    #[agent(skip)] position: shakmaty::Chess,
    #[agent(skip)] history: Vec<(shakmaty::Chess, String /*uci*/, String /*san*/)>,
    #[agent(skip)] selected: Option<shakmaty::Square>,
}
#[actions]
impl Board {
    /// Play a move in UCI notation, e.g. e2e4 or e7e8q.
    fn r#move(&mut self, uci: String) -> Result<String /*SAN*/, ActionError>;   // agent-visible name "move"
    /// Take back the last move.
    #[action(enabled = Self::can_undo)] fn undo(&mut self);
    /// Start a new game.
    fn reset(&mut self);
}
```
(If raw identifiers trip the macro, name the method `play` with `#[action(name = "move")]`.)
- Illegal move → `ActionError::Rejected(format!("illegal move {uci} (legal: {list})"))` where list
  is every legal UCI move, space-separated, sorted. This lets an agent recover in one call.
- Game over → `move` is disabled (`is_enabled` false) and `status` set.
- Typed API for the GUI (NOT actions: `#[action(skip)]` or `&self`): `piece_at(sq) -> Option<Piece>`,
  `selected()`, `legal_targets(from) -> Vec<Square>`, `history_san() -> Vec<String>`,
  and `click(&mut self, sq) -> ClickOutcome` implementing human click-click: select own piece;
  click a legal target → play it (auto-queen on promotion); click elsewhere → reselect/deselect.

## `src/app.rs` — `ChessApp`
```rust
pub struct ChessApp { pub ui: Ui, pub board: Handle<Board>, pub metrics: Metrics, _server: Option<ipc::ServerGuard> }
impl ChessApp {
    pub fn new() -> Self;                                  // mounts Board labelled "Chess board"
    pub fn serve(&mut self, name: &str) -> Result<(), IpcError>; // ipc::Server named `name` with: command("a11y", tree/click handler), observe(metrics)
}
```
Only the board is mounted as a primitive. The GUI's own buttons (New game / Undo) call board
actions with `ChangeSource::User`; they are not separate agent components (the agent has
`reset`/`undo` on the board itself).

## `src/a11y.rs` — the baseline automation surface
`a11y tree` returns a compact JSON accessibility tree of what is on screen, the way generic
automation sees it — it knows nothing about chess semantics beyond visible text:
```json
{"role":"window","name":"rust-use chess","children":[
 {"id":"n1","role":"toolbar","children":[{"id":"n2","role":"button","name":"New game"},{"id":"n3","role":"button","name":"Undo","disabled":false}]},
 {"id":"n4","role":"status","name":"White to move"},
 {"id":"n5","role":"grid","name":"Chess board","children":[
   {"id":"n6","role":"gridcell","name":"a8","value":"black rook","selected":false,"bounds":[0,0,64,64]}, … 64 cells, rank 8→1, file a→h …]},
 {"id":"n70","role":"list","name":"Moves","children":[{"role":"listitem","name":"1. e4 e5"}, …]}]}
```
- Single-line JSON via serde_json (not pretty). Empty squares have `"value":""`. Include `bounds`
  (x,y,w,h in px from the board origin at 64px per square) — real automation trees carry them.
- `a11y click <id>` performs exactly what a mouse click on that element does (board `click`,
  New game → reset, Undo → undo), with `ChangeSource::User`, and replies `{"ok":true}` or
  `{"ok":false,"error":"…"}`. It does NOT return the new tree (generic click tools don't).
- `a11y type <text>` → `{"ok":false,"error":"no focused text field"}` (exists for tool parity).
- Ids are stable for the life of the app (n6..n69 always the same squares).

## `src/metrics.rs`
`Metrics` (Arc<Mutex<…>>, Clone): per transport kind (`Native` = agent text protocol,
`Baseline` = `a11y …` commands) count calls, request bytes, reply bytes, total and mean latency,
and estimated tokens = (request+reply bytes)/4 rounded up. `Metrics::snapshot() -> MetricsView`
for the UI. Fed from `Server::observe`. Also expose `reset()`.
