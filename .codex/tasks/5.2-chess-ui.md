# Task 5.2 — Chess demo: the GPUI window

Read first: `demos/chess/src` (Board, ChessApp, Metrics, a11y), `crates/rust-use-gpui`
(UiExt::bind, HandleExt::on_click / on_mouse_down), gpui 0.2.2 sources and examples at
`~/.cargo/registry/src/*/gpui-0.2.2/examples` (img, div styling, Application::new().run,
WindowOptions). Look at the design reference image `demos/chess/assets/reference/board-reference.png`
(open it — it is the visual target). **Do NOT run `git commit`.**

## Visual design (match the reference)
- Window background: warm charcoal `#262522`. Board sits in a frame with 10px rounded corners,
  no border, subtle shadow.
- Light squares `#EBECD0`, dark squares `#779556`-ish green — sample the reference: light ≈
  `#EAEDD0`, dark ≈ `#7B9A5A`. Use exactly `0xEBECD0` and `0x7B9A5A`.
- Pieces: `demos/chess/assets/pieces/{w,b}{K,Q,R,B,N,P}.svg` rendered with gpui `img()` (it
  rasterizes SVG in full colour via usvg). Piece fills ~86% of the square, centered. Load them
  through an `AssetSource` that embeds the files with `include_bytes!` so the binary runs from
  any working directory.
- Square size 80px (board 640×640). Coordinates: file letters on the bottom rank and rank numbers
  on the a-file, drawn inside the square corners in the opposite square colour, small (11px, semibold).
- Selected square: overlay `rgba(255,255,51,0.5)`. Last move from/to: `rgba(255,255,51,0.35)`.
  Legal targets of the selected piece: a centered dot (28% of square, `rgba(0,0,0,0.14)`) on
  empty squares, a ring on captures. King in check: radial red tint.
- Right side panel (300px wide, same background, 16px padding, rounded cards `#302E2B`, text
  `#E8E6E3`, muted `#9A9894`):
  1. Header: logo-less title "rust-use chess" and a one-line subtitle "Agents play through
     behaviors, not pixels".
  2. Status card: whose turn / check / checkmate result.
  3. Moves card: SAN move list in two columns (move number, white, black), scrolls.
  4. **Agent traffic** card — the live benchmark readout from `Metrics`, one column per transport:
     "rust-use" (Native) and "Generic automation" (Baseline): calls, bytes in/out, ≈tokens,
     mean latency (µs/ms). Highlight the active transport (the one that received the last request).
     A small "Reset" text button clears metrics.
  5. Buttons: "New game", "Undo" (disabled style when unavailable) — they invoke board actions
     with `ChangeSource::User`.
- Everything re-renders via `ui.bind(cx)` when an agent moves over IPC.

## Interaction
- Click-click to move (Board::click), using `on_mouse_down` on each square.
- Promotion auto-queens (already in Board).
- Keyboard: `cmd-z` undo, `cmd-n` new game (gpui actions + key bindings).

## Structure
`demos/chess/src/main.rs` (≤ 60 lines: env/args, Application::new().with_assets(..).run(..),
open window 980×720 titled "rust-use chess", `ChessApp::serve("chess")` so agents can connect with
`rust-use --app chess …`), `src/view/{mod,board,panel,theme}.rs`. Keep colours in `theme.rs`
as named consts. No magic numbers scattered through render code.

`cargo run -p chess-demo` opens the window. Print one line to stderr on start:
`rust-use chess: agents can connect with \`rust-use --app chess snapshot\``.
