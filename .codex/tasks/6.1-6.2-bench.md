Read first: `demos/chess` (OPERA_GAME in src/games.rs, ChessApp, a11y, Metrics),
`demos/chess-mcp-baseline`, `crates/rust-use-cli`. **Do NOT run `git commit`.**
Do NOT run `claude` yourself — the architect runs the LLM sessions. Make scripts that work.

## 6.1 — Scripted micro-benchmark (`bench/`, package `rust-use-bench`, publish = false, workspace member)
`criterion = "0.7"` is in the cargo cache. Benches in `bench/benches/transport.rs`:
1. `in_process/snapshot` and `in_process/act_move` — Agent on a ChessApp Ui.
2. `ipc/snapshot`, `ipc/act_move` — through `ipc::Client` to a server in the same process.
3. `baseline_ipc/tree`, `baseline_ipc/click` — the `a11y` commands through the same IPC.
4. `replay/opera_native` — the whole Opera Game via one `act` per move + reset, and
   `replay/opera_baseline` — via tree + 2 clicks per move (what a generic agent must do) + reset.
Also a binary `bench/src/bin/wire.rs` that replays the Opera Game both ways over IPC and prints a
markdown table of: requests, request bytes, reply bytes, ≈tokens (bytes/4), wall time — per
variant, plus the ratio. Write it also as JSON to `bench/results/wire-<yyyy-mm-dd>.json`. Variants:
- `rust-use (act per move)` — 1 snapshot + 33 acts (each reply already contains the diff).
- `rust-use (one batched act)` — 1 snapshot + 1 act with all 33 steps.
- `generic automation` — per move: get tree, click, click; plus a final tree (must read the
  tree each move to find element ids and confirm the result, as an agent would).

## 6.2 — Claude Code runner (`bench/claude/`)
- `bench/claude/mcp-baseline.json`, `bench/claude/mcp-rust-use.json`, `bench/claude/mcp-none.json`
  (MCP configs; commands reference the release binaries in `target/release`, path made absolute by the script).
- `bench/claude/prompt.md` — the task, identical for all variants except ONE line naming the
  interface (see run.sh). Content: a chess app is open; play exactly this game for both sides, in
  order, one move at a time as written: `1.e4 e5 2.Nf3 d6 3.d4 Bg4 4.dxe5 Bxf3 5.Qxf3 dxe5 6.Bc4 Nf6
  7.Qb3 Qe7 8.Nc3 c6 9.Bg5 b5 10.Nxb5 cxb5 11.Bxb5+ Nbd7 12.O-O-O Rd8 13.Rxd7 Rxd7 14.Rd1 Qe6
  15.Bxd7+ Nxd7 16.Qb8+ Nxb8 17.Rd8#`; use only the tools provided to operate the app; reply DONE
  when the final move is on the board.
- `bench/claude/run.sh [--runs N] [--model M] [--variants a,b,c]` (bash, `set -euo pipefail`):
  1. `cargo build --release -p chess-demo -p rust-use-cli -p chess-mcp-baseline`.
  2. Requires the chess app to already be running (check with `rust-use list`; print how to start it otherwise).
  3. For each variant and run: reset board (`rust-use --app chess act board reset`) and metrics
     (`rust-use --app chess raw metrics reset` — add a `metrics` custom command to the demo server
     returning Metrics JSON, and `metrics reset`), then run in a fresh empty temp dir:
     ```
     claude -p "$PROMPT" --output-format stream-json --verbose --no-session-persistence \
       --setting-sources "" --strict-mcp-config --mcp-config <cfg> \
       --tools <tools> --allowedTools <allowed> --model "$MODEL" --max-budget-usd 3 \
       > raw/<variant>-<n>.jsonl
     ```
     - A `generic`: cfg=mcp-baseline.json, tools="", allowed="mcp__ui-automation__*",
       interface line: "Operate the app through the ui-automation tools."
     - B `rust-use-cli`: cfg=mcp-none.json, tools="Bash", allowed="Bash(rust-use:*)",
       interface line: "Operate the app with the `rust-use` command in the shell (start with `rust-use --help`)." (put the release dir on PATH)
     - C `rust-use-mcp`: cfg=mcp-rust-use.json (`rust-use mcp --app chess`), tools="",
       allowed="mcp__rust-use__*", interface line: "Operate the app through the rust-use tools."
  4. After each run, verify success by checking the board snapshot shows `status=checkmate` and
     the expected final FEN; record app-side metrics JSON.
- `bench/claude/aggregate.py` (python3 stdlib only): parse `raw/*.jsonl` (`type=="result"` message:
  `duration_ms`, `total_cost_usd`, `num_turns`, `usage` incl. cache tokens; count `tool_use` blocks
  in `type=="assistant"` messages), plus the app metrics; output medians per variant to
  `bench/results/claude-<date>.json` and a markdown table to stdout:
  | | Tool calls | Input tokens (incl. cache) | Output tokens | Time | Cost | Success |
- `bench/README.md`: method, fairness notes (same app, same prompt except the interface line,
  same model, compact JSON for the baseline tree, tool description budgets equal), exact commands.
- `bench/results/raw/` is gitignored; aggregated JSON is committed.
