# Task 9.1 — Stop probing `query` on every snapshot; cheaper action lookups

Read AGENTS.md first. **Do NOT run `git commit`.**

## Problem (found in review)
1. `crates/rust-use-agent/src/agent.rs` `queryable()` calls `ui.query(id, &probe)` for EVERY
   component on EVERY `snapshot`/`diff`, just to learn which ones answer `query`. For a `List`, that
   runs `List::query` → `Page::from_iter`, which serializes **every item** to count `total`. A
   10k-row list therefore costs 10k serde serializations per snapshot.
2. `Behavior::actions()` returns a fresh `Vec`. The derived `is_enabled` (in
   `crates/rust-use-macros/src/derive.rs`) calls `Behavior::actions(&self.<behavior>)` once per
   embedded behavior for every action it checks, and `Ui::component` checks every action → O(actions²)
   allocations per snapshot line.

## Changes

### rust-use-core (`src/behavior.rs`)
Add two provided methods to `Behavior` (keep both cheap, both documented with an example):
```rust
/// Whether this behavior answers [`Behavior::query`]. Checked on every snapshot, so it must not
/// do the query's work. Default `false`.
fn queryable(&self) -> bool { false }
/// Whether this behavior owns `action`. Default: scans [`Behavior::actions`]. Composites
/// override it to avoid allocating.
fn owns(&self, action: &str) -> bool { self.actions().iter().any(|a| a.name == action) }
```
- `List` implements `queryable() -> true`. Check every other behavior in `src/behaviors/` and
  implement `queryable` wherever `query` returns `Some`.
- Behaviors with a `const ACTIONS` table override `owns` to scan that table (no allocation).
- `ComponentInfo` gets `pub queryable: bool`, filled by `Ui::component` from `Behavior::queryable`.

### List::query (`src/behaviors/list.rs`) and `Page`
- When there is no text and no custom filter: `total = len`, and serialize only the items in
  `[from, from+limit)`. No full-list serialization.
- With text: still has to scan; keep it, but avoid `to_value(...).to_string()` twice per item.
- Add `Page::window` (or similar) helper if it makes this clean; keep `Page::from_iter` working.

### rust-use-macros (`src/derive.rs`)
- Generated `queryable`: `false || self.<b1>.queryable() || ...` (OR of embedded behaviors).
- Generated `owns`: own `ACTIONS` (via `OwnActions::ACTIONS`) scan, then each behavior's `owns`.
- Generated `is_enabled`: use `owns` instead of `Behavior::actions(..).iter().any(..)`.

### rust-use-agent (`src/agent.rs`)
- Delete the probing in `queryable()`; use `ComponentInfo::queryable`. Remove the `queryable`
  sets from `Snapshot`/`Diff` if they become redundant (keep rendering identical: `?query` on the
  same components as before).
