# Task 9.2 — Session ids: keep the CLI's `diff` correct across app restarts

Read AGENTS.md, `crates/rust-use-agent/FORMAT.md`, `crates/rust-use-cli/src/{state.rs,commands.rs}`.
**Do NOT run `git commit`.**

## Problem (found in review)
The CLI persists the last revision it saw per app (`<name>.rev`) and sends `diff <rev>`. When the
app restarts, its `Ui` revision starts again at 0, so a saved revision from the previous run makes
`diff` report nothing (or the wrong things) without any error.

## Changes
1. **`rust-use-core`**: `Ui::session(&self) -> u64`, a random id fixed when the `Ui` is created.
   No new dependencies: derive it from `std::collections::hash_map::RandomState` hashing the
   current time, the process id and a static counter. Never 0. Document that it identifies one
   `Ui` instance, not a user.
2. **Protocol** (`Agent::handle` and FORMAT.md): a new `hello` request whose reply is one line
   `rust-use <crate version> session <16 hex digits> rev <n>`. Add a FORMAT.md section.
3. **CLI state**: store `<session hex>:<rev>` in the state file (and still read a legacy bare
   number as "unknown session"). Before `diff`, the CLI sends `hello` on the same connection; if
   the session differs from the stored one, or the stored revision is greater than the current
   one, it sends `diff 0` and prints a first line `# app restarted; showing everything` before the
   reply. Keep the extra round trip on the same connection.
4. Keep the state-file write atomic (write to `<name>.rev.tmp`, then rename).

## Tests
- `crates/rust-use-cli/tests/cli.rs`: start a server for Ui A, run `snapshot` then `act`. Drop the
  server, start a NEW Ui B on the same endpoint name with different contents, and run `diff`: the
  output must show B's components and the restart notice, not an empty `rev` line.
- Unit test: two `Ui::new()` calls produce different non-zero sessions; `hello` parses.
