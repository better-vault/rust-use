# Task 9.3 — Cap snapshots, page the rest, and search components with `query`

Read AGENTS.md, `crates/rust-use-agent/FORMAT.md` (the contract) and `src/{agent.rs,format.rs,parse.rs,types.rs}`.
**Do NOT run `git commit`.**

## Problem (found in review)
A `snapshot` returns every component in one reply. A screen with hundreds of components blows the
token budget that rust-use exists to protect. ui-sdk caps snapshots at 100 entries and pages the rest.

## Changes
1. `SnapshotOptions { docs: bool, limit: usize, from: Option<ComponentId> }`, implementing `Default`
   with `limit: 100`. Lines start at `from` (inclusive, by id order). After `limit` lines, emit one
   final line: `more <remaining count> from=@<next id>`. Nothing extra when everything fits.
2. Protocol: `snapshot [--verbose] [--from @id] [--limit n]`. CLI: `rust-use snapshot --from @101 --limit 50`.
   MCP `snapshot` tool: optional `from` (string) and `limit` (int) inputs, with descriptions still
   within the existing 600-character total budget for all three tools (test enforces it).
3. `diff` is not capped. It is already bounded by what changed. Document that.
4. **Component search with `query`.** Today `query <ref> [text]` pages one component's options.
   Add component search when the first argument is a flag: `query --kind <kind> [text]` and
   `query --text <text>`. These return matching component lines in snapshot format (label, kind or
   value contains the text, case-insensitive), capped the same way with `more`. `Agent::search(..)`
   is the typed API. Keep the existing `query <ref>` behavior unchanged.
5. FORMAT.md: document the `more` line, `--from`/`--limit`, and component search, with examples
   that the insta tests check byte for byte.

## Tests
- `tests/budget.rs`: 250 components, default snapshot: 100 lines plus `more 150 from=@101`, then
  `--from @101`, then `--from @201` (the last page has no `more`).
- Component search by kind and by text, including the cap.
- MCP tool description budget test still passes.
